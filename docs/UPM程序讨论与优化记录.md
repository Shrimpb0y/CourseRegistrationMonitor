## 下一轮讨论

### 用户新增明确需求

1. **复用与目标选择**：不能只服务于预设课程。需要在界面中加入课程选择、组别选择及对应时间选择；课程、组别、完整时间之间应关联，并能保存为可复用目标。当前配置可修改，但缺少用户可操作的选择界面，不满足此体验要求。
2. **Launcher 与统一自动化界面**：需要方便启动的本地 launcher，以及整合后的自动化管理界面，减少手工运行命令、修改 JSON 与分散操作。launcher 的安装形式、是否托盘常驻及后台启动方式尚待选型。
3. **本轮工作顺序**：先记录需求，再在 GitHub 搜寻对应项目，汇总候选、适配方案和取舍后汇报。本轮不直接替换框架或实施上述新功能。
4. **延续约束**：本地运行，不上传账号、会话和运行记录；UPM 登录仍由用户完成。借用通用界面/桌面框架不等于已有 UPM 选课适配，必须明确新增开发范围。
